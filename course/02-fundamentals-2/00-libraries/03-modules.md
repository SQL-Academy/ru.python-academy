# Модули в Python

Пока каждая ваша программа помещалась в один файл, и этого хватало. Но однажды вы напишете функцию, которая пригодится и в следующей задаче, а перенести её туда получится только копированием. Скопировали в три скрипта, нашли ошибку — правите в трёх местах.

Значит, нужен способ держать код в отдельном файле и подключать оттуда только нужное. Такой файл называется модулем.

## Вы уже пользуетесь модулями

Строка `import math` встречалась вам в главах про библиотеки. Посмотрим внимательнее, что происходит после неё.

```python
import math

print(math.sqrt(144))
<output>
12.0
</output>
print(type(math))
<output>
<class 'module'>
</output>
```

`import` не вставляет текст чужого файла в ваш. Он создаёт **объект-модуль** и кладёт его в переменную с именем `math`. Дальше `math.sqrt` — обычное обращение к атрибуту объекта, точно такое же, как `"строка".upper()`.

> Модуль — это файл с расширением `.py` (у нескольких встроенных модулей вроде `math` файла нет, они вшиты в интерпретатор). Всё, что в нём определено (функции, классы, переменные), становится атрибутами объекта-модуля после импорта.

## Создаём свой модуль

Теперь сделаем такой файл сами. Пусть у нас есть небольшой скрипт, который считает цены: прибавляет НДС и применяет скидки. Сам расчёт положим в `prices.py`, а в `main.py` оставим только вывод результатов:

**prices.py**

```python
"""Расчёт цен: НДС и скидки."""

VAT = 0.2


def with_vat(price):
    """Цена с НДС."""
    return round(price * (1 + VAT), 2)


def discount(price, percent):
    """Цена после скидки в процентах."""
    return round(price * (1 - percent / 100), 2)

```

**main.py**

```python
import prices

print(prices.with_vat(100))  # 120.0
print(prices.discount(1000, 15))  # 850.0
print(prices.VAT)  # 0.2

```

`main.py` пишет `import prices`, и Python находит `prices.py` в той же папке. Имя модуля берётся из имени файла: убираем `.py`, получаем `prices`. Этого достаточно, чтобы импорт заработал.

Раз имя модуля — это имя файла, называйте файлы в snake_case: `user_interface.py`, а не `UserInterface.py`. И не `random.py`: файл, названный как модуль стандартной библиотеки, перекроет настоящий модуль.

## Код модуля выполняется ровно один раз

При импорте Python выполняет файл сверху донизу. В `boot.py` ниже `print` стоит на верхнем уровне, не внутри функции, поэтому сработает при импорте. Импортируем этот модуль двумя строками подряд:

**boot.py**

```python
print("boot.py выполняется")

READY = True

```

**main.py**

```python
import boot
import boot

print("а строк с import было две")

```

```text
boot.py выполняется
а строк с import было две
```

Хотя строк с `import` было две, файл выполнился один раз: готовые модули Python запоминает и при повторном импорте отдаёт тот же объект. Отсюда практический вывод: на верхнем уровне модуля держат определения, а не действия — всё, что там написано, выполнится при первом же импорте, даже если ни одна функция оттуда не понадобится.

## from ... import: имя переезжает к вам

Писать `prices.` перед каждым вызовом надоедает. Форма `from ... import` забирает из модуля конкретное имя и кладёт его прямо в вашу программу. В примере ниже обе формы импорта стоят рядом нарочно, чтобы в последней строке сравнить результат — в обычном коде так не пишут.

**prices.py**

```python
"""Расчёт цен: НДС и скидки."""

VAT = 0.2


def with_vat(price):
    """Цена с НДС."""
    return round(price * (1 + VAT), 2)


def discount(price, percent):
    """Цена после скидки в процентах."""
    return round(price * (1 - percent / 100), 2)

```

**main.py**

```python
import prices
from prices import with_vat

print(with_vat(100))  # 120.0
print(with_vat is prices.with_vat)  # True

```

Последняя строка — самое важное здесь. Никакой копии функции не появилось: `with_vat` и `prices.with_vat` — два имени одного объекта. `from ... import` не «другой способ импорта», а дополнительное действие: сначала модуль импортируется целиком (со всем своим кодом), потом одно из его имён копируется в ваше пространство имён.

Итого у вас три формы, и выбирают между ними так:

- **Функций из модуля нужно много, или важно видеть, откуда взялось имя** — оставьте префикс:

    ```python
    import prices

    print(prices.with_vat(100))
    ```

- **Нужны две-три функции и вызываются они часто** — заберите их по именам, код станет короче:

    ```python
    from prices import with_vat, discount

    print(with_vat(100))
    ```

- **Имя модуля длинное или уже занято вашей переменной** — подключите его под коротким именем:

    ```python
    import prices as p

    print(p.with_vat(100))
    ```

Последняя форма — та самая причина, по которой пишут `import pandas as pd`.

## Как отличить запуск от импорта

Как мы видели, при импорте выполняется весь код модуля. Значит, код внутри `prices.py` отработает в обоих случаях:

```bash
python prices.py   # запускаем сам модуль
python main.py     # запускаем программу, которая его импортирует
```

Но иногда код нужен только при прямом запуске файла. Например, проверка «а верно ли считают функции»: автору она удобна, а тому, кто импортирует модуль, только мешает.

Отличить одно от другого позволяет переменная `__name__`, она есть у каждого модуля. При импорте в ней лежит имя модуля, здесь это `"prices"`. А у файла, который запустили напрямую, там всегда `"__main__"`. Поэтому такое условие истинно только при прямом запуске:

```python
if __name__ == "__main__":
    print("проверка:", with_vat(100))
```

В `prices.py` ниже эта проверка стоит в самом конце, а `main.py` на соседней вкладке просто импортирует модуль:

**prices.py**

```python
"""Расчёт цен: НДС и скидки."""

VAT = 0.2


def with_vat(price):
    """Цена с НДС."""
    return round(price * (1 + VAT), 2)


def discount(price, percent):
    """Цена после скидки в процентах."""
    return round(price * (1 - percent / 100), 2)


if __name__ == "__main__":
    print("проверка:", with_vat(100))

```

**main.py**

```python
import prices

print("итог:", prices.with_vat(100))

```

```text
итог: 120.0
```

Запустили `main.py` — в выводе только его собственная строка: `__name__` внутри `prices.py` равен `"prices"`, условие ложно, проверка промолчала. А при прямом запуске модуля напечаталось бы `проверка: 120.0`.

Так один файл совмещает две роли: набор функций для чужого кода и самостоятельная программа. В этот блок кладут всё, что не должно случаться при импорте: запуск программы, разбор аргументов командной строки, проверки вроде нашей.
